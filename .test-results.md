### Bug — found + FIXED in `d5be494`

- **[bug]** Bad product/category slugs returned **HTTP 200** instead of 404 (`/products/non-existent`, `/category/non-existent`). The 404 body rendered correctly but the status header was wrong, which would hurt SEO (crawlers won't deindex these URLs). Root cause: `safe()` wrapping the data fetch + Next 16 Turbopack streaming commits status before `notFound()` reaches the response layer.
  Fix: removed `safe()` from `getProductBySlug` and `getCategoryBySlug` calls in PDP/category routes. `notFound()` now triggers unambiguously. **In dev mode the status stays 200 (known Next 16 Turbopack quirk); production builds (`next build && next start`) return 404 correctly.** Inline comments explain the limitation.
